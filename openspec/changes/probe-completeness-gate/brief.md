# probe-completeness-gate — stop accepting streams that visibly do not finish

**Status:** Ready to implement. Depends on nothing (it ADDs requirements rather than editing the still-unarchived framing gate); should land before `probe-provenance-unconfirmed`, whose sizing depends on it. Behaviour-changing in the same direction as #261: more junk raises a detection error instead of producing a made-up member. Effort: small for the first half, medium for the second.

**Why it matters:** #261 taught the Brotli probe to check that a declared block length fits inside the file, which cut false positives from 3.5% of a real Linux tree to 0.19%. Measuring what survived turned up something simpler and bigger. The probe decodes a couple of hundred bytes and accepts "the decoder wants more input" as a match — sensible when the file is bigger than what it read, nonsense when it is holding the entire file. Sixty-seven of the leftover false positives are **under sixteen bytes**. A five-byte text file is claimed as Brotli because the probe never asks whether a stream it can see in full actually finishes.

**What it does:** Two rules, both of the same kind as the one that landed — a question the file answers about itself, not a threshold anyone picked. First: if the source is no bigger than the bytes the probe was handed, a decode that ends wanting more input is a rejection, because a complete stream decoded in full terminates. That is 71% of the remaining false positives for no extra reading and no interface change, and it cannot cost a real stream, because a real stream decodes to completion by definition. Second: the chain walk deferred from #255 — follow the format's self-describing blocks and check each one fits — which is the only thing that helps files above about 16 MiB, where the length field's ceiling makes the first check meaningless.

**Decided:** Completeness applies to every decoding probe, not just Brotli, because it follows from bounded decoding rather than from Brotli's framing. It must not be written as a minimum file size — a nine-byte real Brotli file has to survive. Hitting the chain walk's link limit means *cannot disprove*, so the earlier verdict stands rather than becoming a rejection. Confidence levels and error messages are deliberately untouched; they belong to the sibling change. The compound-document family that survives both rules stays a documented residual, not a magic denylist.

**Your call later:** One — who performs the chain walk's reads. The probe contract currently forbids reading past the prefix, and the walk needs bytes at offsets beyond it. Three shapes are written up with costs; the recommendation is an optional bounded read callback, so a probe that ignores it behaves exactly as today. Worth an implementer's eye on the real call sites before committing.

**Bottom line:** The expensive half of this was already measured; the cheap half turned out to be the valuable one. Completeness alone takes the residual from 128 fabricated claims to 37 on the tree it was measured against.
