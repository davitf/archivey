# probe-provenance-unconfirmed — tell the caller when nothing but a guess identified the file

**Status:** Ready to implement. `brotli-probe-framing-gate` is archived and synced in this same PR, so its requirements are live and these deltas are written against shipped text. `probe-completeness-gate` should still land first, so the numbers quoted here are current. Behaviour-changing only in what failures *say*, never in which reads fail. Effort: small.

**Why it matters:** #261 added an honesty signal. When archivey identifies a file purely by decoding a bit of it and the read later fails, the error now says so — the format may have been wrong — instead of blaming the file for being truncated. Good idea, wired to the wrong switch. It fires on the *confidence level* detection reported, and confidence answers a different question. On a scan of 66 361 real files, 128 files were claimed as a compressed format they are not, and **68 of them — over half — produce a failure that carries no signal at all**, because their probe happens to report "probable". A Mach-O executable with a 7z archive appended to it does exactly this today: it is announced as an LZMA file, listed with one invented member, and fails with an error that vouches for the identification.

**What it does:** Switches the trigger from "how confident was detection" to "did anything at all corroborate the probe" — a matching file extension, or a TAR header found inside after decompressing. Neither is a confidence level; both are a second, independent thing agreeing. A probe hit with nothing behind it gets the signal regardless of the number detection printed next to it. Also folds in the TAR case, which currently gets no credit for having actually decompressed successfully into something recognisable.

**Decided:** The rule names no probes — "a probe said so and nothing else did" covers any probe added later without an edit. Confidence values themselves are untouched; the point is to stop them steering exception behaviour, which had already bent one detection decision (compressed-first Brotli was moved to "probable" *in order to* dodge the flag). Nothing here creates new failures: a probe-only file that reads cleanly stays a success, exactly as #261 decided. The exception types stay too — `except TruncatedError` must keep working.

**Your call later:** Whether the corroboration fact should be visible on the detection result itself, so a caller can ask "was this identification backed by anything?" before reading rather than only learning it from an error. Left out to keep this change small.

**Bottom line:** The signal already exists and already works; it is just pointed at one class of file when the problem it describes is general. Fixing that is a rename, a dropped condition, and a message that stops mentioning a confidence level.
