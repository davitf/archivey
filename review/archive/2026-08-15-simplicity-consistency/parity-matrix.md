## Disagreements

### F1 — `seekable_members` decides whether metadata exists

**Expected** (rows H1/H5, and `format-single-file-compressors`): `member.size` follows
the per-codec table; `member.hashes` carries a stored digest "when readable **without
decompressing**". Neither statement mentions the caller's declared stream capabilities.

**Observed** — the full flag × source-shape cross:

| Key | Source | `seekable_members=False` | `seekable_members=True` |
|---|---|---|---|
| `gz` | Path | size `None`, hashes `{crc32}` | size `None`, hashes `{crc32}` |
| `gz` | `BytesIO` | size `None`, hashes `{crc32}` | size `None`, hashes `{crc32}` |
| `lz` | Path | size `None`, hashes **`{}`** | size **`44`**, hashes **`{crc32}`** |
| `lz` | `BytesIO` | size `None`, hashes **`{}`** | size **`44`**, hashes **`{crc32}`** |
| `xz` | Path | size **`None`** | size **`44`** |
| `xz` | `BytesIO` | size **`None`** | size **`44`** |
| `zst`, `lz4` | either | size `None` | size `None` (corpus frames carry no content-size) |

Same through the other entry point: `open_stream(p, seekable=False).size` is `None` for
`.lz`/`.xz` and `44` with `seekable=True`. **The two entry points agree with each
other** — this is not an entry-point split.

**Source shape is irrelevant.** `Path` and seekable `BytesIO` give identical answers, so
this is **not** seed A2 (Path-gating). The seeds did not point here; the expected-column
counterweight is what surfaced it.

**O-21 trace.**

1. `codecs.py:1187` — `_SizedLzmaCodec.extract_metadata` sets
   `member.size = ctx.probe_decompressed_size()`. Serves both XZ and lzip.
2. `single_file_reader.py:318` — `_probe_decompressed_size` opens the codec through
   `resolve_codec(self._codec, self._codec_config)` and calls
   `DecompressorStream.try_get_size()`.
3. `codecs.py:1199` — `XzCodec.open` → `XzDecompressorStream(source, seekable=config.seekable)`.
   The index that holds the size is only parsed on the seekable path, so `try_get_size()`
   returns `None` otherwise.
4. `single_file_reader.py:294` — `_probe_lzip_index` short-circuits explicitly:
   `if not self._codec_config.seekable: return None`. Its docstring says
   *"Gated on declared SEEKABLE, which is what enables the index scan"* — a conscious
   choice, correctly commented, whose caller-visible consequence was not traced.
5. **The branch where the happy path does not hold** is the default one: `seekable` is
   `False` unless the caller opted in, so the *default* open is the metadata-poor one.
6. **Contrast, same file:** `GzipCodec` reads its CRC-32 from `ctx.peek_trailer(...)` and
   `LzmaAloneCodec` reads its size from `ctx.peek_header(...)` — bounded peeks, no
   decompressor, no flag. Three of five codecs are ungated; two are gated *because they
   reuse the decompressor*.

**Spec check** (before calling it a docs bug — three outcomes, only one is a docs fix):

- **XZ** — `format-single-file-compressors`: *"XZ, ZST | Header size when encoder wrote
  it; otherwise `None`"*. **No seekability condition.** Code diverges from spec →
  spec fiction / defect, not a docs fix.
- **LZIP** — same spec: *"Available from the trailer through the seekable lzip
  backend"*, and the digest scenario row *"Single-member `.lz`, seekable lzip index |
  `CRC32` present"*. The code matches, but the spec is phrased in **implementation
  terms**. A reader cannot tell from it that a plain `open_archive(path)` gets nothing.
- **Nothing** in `archive-reading` or `access-mode-and-cost` licenses a declared
  capability to change metadata. `access-mode-and-cost` says the capabilities "declare
  stream capabilities **within** a mode" — a statement about streams, not members.

**Classification: accident.** "Format law" needs a citation and there is none: the lzip
trailer and the xz index are both bounded reads over a source that is *already*
seekable, which is exactly what gzip does unconditionally two rows up. "I could not see
how to avoid it" would be an accident with an unknown fix; here the fix is visible.

**VISION impact.** `VISION.md` names dedupe as the founding use case and *"hashes without
decompression where possible"* as a core priority. `open_archive(p)` on a `.lz` returns
no CRC-32 today. `docs/gotchas.md`'s `seekable_members` bullet describes only the
`seek()` and rewind-cost consequences — true, and incomplete, because the flag does two
unrelated things.

**Guardrails:** `test_declared_seekability_changes_member_size` (pin),
`test_gzip_crc32_is_not_gated_on_declared_seekability` (the target shape),
`test_member_size_does_not_depend_on_declared_seekability` +
`test_lzip_surfaces_crc32_without_declaring_seekable_members` (strict-xfail red halves).

### F6 — directory backend vs the index-topology table

**Expected** (row R6, from `access-mode-and-cost`'s index-topology table):

> | Leading (directory, ISO) | Both modes, as complete report |

**Observed:**

| Backend | `members_report_if_available()` before any pass | `listing_cost` |
|---|---|---|
| `dir` | **`None`** in both modes | `requires_scanning` |
| `iso` | complete report (n=7, `error=None`) | `indexed` |
| `zip` / `7z` | complete report | `indexed` |
| `tar` family | `None` (correct — no-index row) | `requires_scanning` / `requires_decompression` |
| single-file | complete report (n=1) | `indexed` |

**O-21 trace.** The directory backend does not build an upfront member table; it walks
the tree on demand, which is *also* why its `listing_cost` is `REQUIRES_SCANNING` — the
code is at least self-consistent. The spec groups directory with ISO purely by "the
index is at the front", which is true of ISO's volume descriptors and simply not a
property a live filesystem tree has.

**Classification: spec↔code disagreement — not resolvable by a reviewer.**
`CONTRIBUTING.md` and `AGENTS.md` both require pausing here rather than picking a
winner, and the two fixes are genuinely different products:

- *Fix the spec* — drop `directory` from the leading-index row. Cheap, honest, and
  consistent with `listing_cost=REQUIRES_SCANNING`.
- *Fix the code* — have the directory backend materialize on open. Buys the peek, costs
  an eager `os.walk` on every open, and would make `listing_cost` a lie unless that
  changes too.

Note the coupling: whichever side moves, `listing_cost` and the topology table must end
up telling the same story. → **Q6**.

### F7 — an asserted format that is wrong can succeed

**Expected** (row E6, generalizing `archive-reading`'s directory rule): an explicit
`format=` that the source cannot be is refused, not silently honoured over wrong data.
The spec only states this for the directory case.

**Observed:**

| Case | Result |
|---|---|
| `open_archive(zip, format=TAR)` | `CorruptionError` ✅ |
| `open_archive(gz, format=TAR)` | `TruncatedError` ✅ |
| `open_archive(7z, format=TAR)` | `TruncatedError` ✅ |
| `open_archive(dir, format=ZIP)` | `ArchiveyUsageError` ✅ (#225) |
| **`open_archive(iso, format=TAR)`** | **opens; `reader.format == TAR`; `members() == []`; no error; no diagnostic** |
| same, `strict_archive_eof=True` | **identical — still 0 members, still silent** |

**O-21 trace.** An ISO 9660 image begins with a 32 KiB zero-filled system area. A TAR
end-of-archive marker is two zero blocks. So the TAR reader is not malfunctioning — it
is correctly reading a valid, empty TAR archive. The branch where the happy path does
not hold is the *escape hatch*: `strict_archive_eof=True` is documented as the knob for
"I need a provably complete listing", and it does not fire, because the trailer is
present and well-formed.

**Classification: accident with a format-law component.** The TAR reading is format law
and citable. What is *not* format law is that `open_archive` performs no plausibility
check when the caller has explicitly asserted a format — the same reasoning
`reject-format-override-on-directory` accepted for directories ("the wrong data,
succeeding") applies unchanged. Whether the answer is a post-open plausibility gate, a
diagnostic, or "accept it, TAR is TAR" is a product call. → **Q7**.

### F2 — `encoding=` accepted and discarded

**Expected** (§Rows the specs do not decide, item 6): no spec generalizes the
directory-`format=` rule to other discarded arguments, so this had to be *decided*
rather than checked.

**Observed** — passing `encoding="cp500"` (EBCDIC re-maps even ASCII, so "unchanged"
means "never applied", not "this corpus has no non-ASCII names"):

| Backend | Names change? | Verdict |
|---|---|---|
| ZIP | changed | honoured (and specced — `format-zip` requires an explicit `encoding=` to disable the UTF-8 sniff) |
| TAR / compressed TAR | changed | honoured |
| ISO | unchanged | **silently discarded** |
| 7z | unchanged | **silently discarded** |
| directory | unchanged | **silently discarded** |
| single-file | unchanged | **silently discarded** |

For 7z (UTF-16 names) and single-file (name from the filesystem) the *behaviour* is
right — there is nothing to decode. ISO is the awkward one: it genuinely has encoding
choices (Joliet UCS-2 vs Rock Ridge), the detector already produces an `encoding_hint`,
and the caller's explicit override is dropped on the floor anyway.

**Classification: accident.** Not because the backends should decode differently, but
because #225/P8 already decided that discarding an explicit caller assertion is the
wrong shape, and that decision was applied to one argument only. → **Q2**.

### F8 — pipe capability is behaviour, not data

**Expected** (row E4): format-forced, "and the question is only whether it is
*queryable*."

**Observed:** the behaviour half is **fine** — one typed error, one message shape,
identical from `open_archive` and `extract()`:

```
StreamNotSeekableError: Format ArchiveFormat.ZIP cannot be read from a non-seekable
source even in streaming mode (its index/metadata is not at the front of the stream).
Buffer it to disk or a BytesIO and reopen.
```

The queryable half is missing. `FormatAvailability` exposes `format`, `support`,
`missing` — nothing about source shapes. The fact exists as
`ReadBackend.SUPPORTS_STREAMING_NON_SEEKABLE`, which is `internal/`. A caller writing
"pipe this if you can, else buffer it" must try-and-catch.

**Classification: accident, with real freeze-cost** — `FormatAvailability` is public and
its field set freezes at `0.2.0`. → **Q8**.

### F11 — the entry points disagree about directories

| Call | Result |
|---|---|
| `open_archive(missing_path)` | `FileNotFoundError` from the OS (correct per `error-handling`: filesystem `OSError` propagates unchanged) |
| `open_stream(missing_path)` | hand-rolled `FileNotFoundError("Compressed stream not found: …")` |
| `open_archive(directory)` | **opens** as `DIRECTORY` |
| `open_stream(directory)` | **`FileNotFoundError("Compressed stream not found: …")`** — for a path that exists |
| `open_archive(42)` / `open_stream(42)` | `TypeError` both, different messages (fine) |

**O-21 trace.** `core.py:332` — `if not path.is_file(): raise FileNotFoundError(...)`.
One predicate collapses two distinct situations, and the message asserts the false one.

**Classification: accident.** Small, but it is the "same concept → same failure mode"
value in miniature: the two entry points give a caller two different stories about the
same path. → **Q12**.

### F5 — `compressed_size` is Path-gated on every single-file codec

**Expected** (nothing in `archive-data-model` conditions `compressed_size` on source
shape; #225/O-25 established that probes gate on *seekability*, not on `Path`).

**Observed** — probe rows `H3` (Path) vs `H6` (seekable `BytesIO`):

| Family | `compressed_size` from `Path` | from `BytesIO` |
|---|---|---|
| `gz`, `gz-meta`, `bz2`, `xz`, `zst`, `lz4`, `lz`, `zz`, `br` | `int` | **`None`** |
| `zip`, `zip-aes`, `iso`, `iso-joliet`, `7z` | `int` | `int` |
| `tar` family | `None` | `None` (a TAR member has no separate compressed size) |

**O-21 trace.** `single_file_reader.py:173` —
`os.path.getsize(self._source) if isinstance(self._source, Path) and self._source.exists() else None`.
There is no seekable-stream fallback, although `_with_seekable_source` sits a few lines
below and already gives every other probe on that class a handle for both shapes.

**Classification: accident**, and the narrowest one in the review — the fix is a
`SEEK_END` on the branch that currently returns `None`. It is the residual the #225
Path/seekable sweep did not reach, which is precisely why the first pass's "seed A2 is
clean" verdict was wrong.

**Guardrails:** `test_single_file_compressed_size_is_path_gated` (pin, all 8 codecs),
`test_single_file_compressed_size_is_not_path_gated` (red half),
`test_container_formats_report_compressed_size_from_either_shape` (the target shape).

### F9 — header encryption is not lazy, and the guide does not say so

**Observed** — probe row `E9`, opening a header-encrypting corpus entry with **no**
password:

| Archive | `open_archive(path)` with no password |
|---|---|
| 7z, `-mhe` (header-encrypted) | `EncryptionError: Password required to decrypt the 7z header` |
| RAR, encrypted headers (`tests/fixtures/rar/encrypted_header__.rar`) | `EncryptionError: RAR archive has encrypted headers but no password was provided` |
| ZIP / 7z / RAR with **data**-only encryption | opens and lists fine; the password is asked for at member read |

**Classification: format law** — the listing itself is ciphertext, so there is nothing
to be lazy about. The finding is the **docs** half: `docs/reading-members.md:74–77`
states the laziness rule unbounded —

> **Nothing is decompressed until you read.** A member you skip is never opened, and no
> password is requested for it.

— which is true for data encryption and false for a header-encrypted archive, where the
loop that bullet describes never gets to exist. `docs/formats.md` documents the header
cases; the two pages need to agree. → **Q9**.

**Correction this forces:** the first pass reported "no password work at
`open_archive()` for any probed format, including 7z header-encrypted". Its probe passed
the corpus entry's password, so the row was never exercised. The corrected statement is
the bounded one above.

**Guardrails:** `test_header_encrypted_7z_needs_the_password_at_open`,
`test_data_encrypted_members_still_list_without_a_password`.
