# Proposed documentation outline (code-derived)

Ordered by what a new user needs first. Proportions are rough shares of a
focused guide (not including generated API reference). Argue from failure cost,
not from “nice to have”.

---

## 0. Landing / install (~5%)

**Purpose:** one screen — what archivey is (read / stream / safely extract),
Python ≥3.11, `pip install archivey` vs extras, link to format availability.

**Breaks without it:** users install the empty core, try RAR/ISO/zstd, and
conclude the library is broken.

Include a **format × extra × external tool** table (ZIP/TAR core; ISO→`[iso]`;
RAR→`[rar]`+RARLAB `unrar`; 7z codecs→`[7z]`; seek accel→`[seekable]`; …)
driven by `format_availability` / `MissingComponent`.

---

## 1. 30-second recipes (~5%)

**Purpose:** four copy-paste blocks — list members, extract safely, stream one
member, open a pipe with `streaming=True`.

**Breaks without it:** first-hour abandonment; people reach for stdlib and never
see safety defaults.

Keep tiny; link out to deep pages.

---

## 2. Safe extraction — **~25% of the guide** (long)

**Purpose:** the page without which the library cannot be used safely on
untrusted input. Policies, overwrite, OnError, bombs, path/symlink/hardlink
rules, duplicate names, CLI vs API defaults.

**Breaks without it:** path escape, symlink write-through, zip bombs, silent
execute-bit retention expectations, false confidence in `TRUSTED` / `STOP`.

→ Sample page A in this deliverable set.

---

## 3. Opening archives: sources, detection, passwords (~10%)

**Purpose:** paths / directories / streams / multi-volume; magic vs extension;
mid-stream `tell()` origin; `encoding=` vs ZIP fallback; password shapes and
ZipCrypto STORED cost; directory override.

**Breaks without it:** `StreamNotSeekableError` confusion; wrong format forced;
multi-volume misuse; password-on-tar surprises.

---

## 4. Access modes, member streams, and cost — **~20%** (long)

**Purpose:** `streaming` vs random access; `MemberStreams`; `CostReceipt`
axes; solid order; when to use `members` vs `stream_members` vs `scan_members`;
listing limits.

**Breaks without it:** `ConcurrentAccessError`, pipe failures, O(n)
redecompression, solid out-of-order errors, memory blowups from `members()` on
huge archives.

→ Sample page B in this deliverable set.

---

## 5. Reading members & `ArchiveStream` (~8%)

**Purpose:** `open`/`read`/`stream_members` contracts; laziness; verify-on-close;
rewind warnings; non-file open refusal; link following; identity `in`.

**Breaks without it:** collecting streams across iteration; unbounded `read()`;
CRC errors appearing “late”.

---

## 6. Formats deep-dive (~12%, split per family)

Pages (or sections):

| Page | Purpose |
|---|---|
| ZIP | codecs, encryption (ZipCrypto/AES), duplicates, encoding |
| TAR / compressed TAR | EOF marker, solid cost, hardlinks, streaming |
| 7z | solid folders, ANTI, method matrix, password KDF cost, BCJ2 reject |
| RAR | native list + unrar data, solid pipe, volumes, file versions |
| ISO | namespaces, pycdlib extra, cycle guard coexistence note |
| Single-file codecs | `open_archive` vs `open_stream`, inner-TAR upgrade |
| Directory | pseudo-archive, TOCTOU diagnostics, listing cost |

**Breaks without it:** format-specific errors look like generic bugs; operators
cannot predict PARTIAL support.

7z/RAR method matrices deserve real length; directory/ISO can be a screen each.

---

## 7. Errors, diagnostics, and limits (~8%)

**Purpose:** exception tree (two roots); translating third-party failures;
`DiagnosticCode` catalogue; policy IGNORE/COLLECT/RAISE; `ResourceLimitError`
vs `FilterRejectionError`; measurement.

**Breaks without it:** swallowed usage errors; ignored `FORMAT_EXTENSION_CONFLICT`;
bomb vs block confusion.

---

## 8. Configuration reference (~4%, dense screen)

**Purpose:** every `ArchiveyConfig` / limits field with defaults and when to
change it (accelerators, `strict_archive_eof`, ZIP encoding, diagnostic
retention).

**Breaks without it:** foot-guns around AUTO vs ON, EOF strictness, silent
listing caps.

---

## 9. CLI (~5%)

**Purpose:** verbs, smart dest, overwrite/policy defaults **called out as
≠ library**, exit codes, passwords on argv warning, reserved verbs.

**Breaks without it:** automation mis-handles exit 3; “why did it make a
subdir?”; API ports get overwrite wrong.

---

## 10. Generated API reference (~separate, large)

**Purpose:** autogenerated from `__all__` + docstrings; demoted symbols noted.
Not prose. Must not be the only docs — signatures omit almost everything in
`must-explain.md`.

---

## 11. Optional / appendix (short)

- **Performance notes:** rapidgzip threshold, solid planning via `CostReceipt`,
  `enable_measurement`.
- **Security considerations:** trust boundaries (dest vs members), what STRICT
  does not claim.
- **Changelog / migration:** out of scope for this outline’s evidence base.

Explicitly **not** proposed as user-facing primary docs: internal threat-model
IDs, OpenSpec text, contributor guides (those are maintainer surfaces).

---

## Proportion summary

| Bucket | Share |
|---|---|
| Safe extraction | ~25% |
| Access / streaming / cost | ~20% |
| Per-format notes | ~12% |
| Open / detect / password | ~10% |
| Reading streams | ~8% |
| Errors / diagnostics | ~8% |
| Install + recipes + CLI + config | ~17% |

If the real guide buries (2) and (4) behind a generic “Usage” page, that is the
failure mode this outline is arguing against.
